# Jira 규칙

팀 가이드 원본은 [C106 개발 가이드](../../docs/development-guide.md) 5절이다. Jira 이슈 생성·수정은 외부 시스템 변경이므로 실행 권한은 [AI 협업 규칙](ai-collaboration.md)을 따른다.

## 프로젝트

- 사이트는 `ssafy.atlassian.net`, 프로젝트 키는 `S15P31C106`이다.
- 이슈를 만들기 전에 프로젝트 키를 확인한다. 비슷한 이슈가 이미 있는지 검색한다.

## 상태

| 상태 | 의미 |
| --- | --- |
| 해야 할 일 | 작업 전 |
| 진행 중 | 구현 중, MR 생성·리뷰 중 |
| 완료 | 병합·검증 완료 |

- 막힌 작업도 상태를 바꾸지 않는다. 선행·후행 작업 항목에 의존 관계를 기록한다.
- 완료로 옮기는 것은 병합과 검증이 끝난 뒤다. 사용자가 요청하지 않으면 완료로 옮기지 않는다.

## 이슈 작성

- 유형은 작업(Task)을 쓴다. 스토리는 쓰지 않는다. 관련 에픽을 상위로 지정한다.
- 제목은 `[영역][도메인] 작업 내용` 형식이다. 영역은 `BE`, `AI`, `FE`, `Infra`, `Docs`이다. 기획·문서 작업은 `Docs`를 쓴다. 도메인은 해당할 때만 붙인다.
- 스토리포인트는 1포인트 = 1시간이다. 1, 2, 3, 5만 쓴다. 5를 넘으면 이슈를 나눈다. 한 사람이 한 주에 40포인트를 넘지 않게 한다.
- 설명은 기능 ID, 목적, 배경·근거, 작업 내용, 산출물, 완료 기준, 담당·검토, 선행·후행 작업, 참고 문서 순서로 쓴다. 해당하지 않는 항목은 생략할 수 있다.
- 완료 기준은 체크박스로 쓴다. 이미 끝난 항목만 체크한다.

## 계정과 담당자

- 연결된 Jira 계정이 작업 요청자와 다를 수 있다. 보고자와 담당자를 자동값으로 두지 말고 사용자에게 확인한다.
- 담당자를 확인할 수 없으면 비워 두고 보고한다.

## 작성 후 확인

- 이슈를 만들거나 고친 뒤 다시 조회해 제목, 상위 에픽, 스토리포인트, 상태, 담당자, 보고자를 확인한다.
- 설명의 체크박스와 목록이 일반 글자로 저장되지 않았는지 확인한다. 깨졌으면 Jira 문서 형식으로 다시 저장한다.
- MR을 만들면 MR 링크를 이슈의 산출물 항목에 추가한다.
