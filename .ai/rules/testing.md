# 테스트 규칙

## 기본 원칙

- 변경사항과 관련된 테스트를 우선 확인한다.
- 테스트가 없으면 필요한 테스트를 제안하거나 작성한다.
- 버그 수정 시 가능하면 재현 테스트를 작성한다.
- 중요한 실패 경로를 검증한다.
- 기존 테스트를 통과시키기 위해 검증을 약화하지 않는다.
- 테스트를 임의로 삭제하거나 Skip하지 않는다.
- 실행하지 않은 테스트를 성공했다고 말하지 않는다.
- 테스트가 실패하면 실패 원인과 영향을 보고한다. 원인을 확인하지 못했으면 미확인으로 표시한다.

명령어는 프로젝트의 문서와 실제 설정에서 확인한다. 이 템플릿에는 공통 테스트 명령이 없다. 테스트 도구나 환경이 없으면 실행 불가 이유와 필요한 검증을 보고한다. 테스트 실행의 권한도 [AI 협업 규칙](ai-collaboration.md)을 따른다.

## Team Decision Needed

다음 항목은 아직 미결정이다. Coverage 수치나 테스트 종류별 의무 기준을 임의로 정하지 않는다.

- Unit Test 필수 기준
- Integration Test 필수 기준
- E2E Test 필수 기준
- Test Naming Convention
- Coverage 기준
- CI 필수 테스트
- 동시성 및 성능 테스트 기준
