# 아키텍처 규칙

이 템플릿은 특정 프로젝트의 아키텍처를 결정하지 않는다. 현재는 기술 중립적인 기본 원칙만 적용한다.

## 기본 원칙

- 이미 확정된 프로젝트 구조와 책임 경계를 존중한다.
- 아키텍처 변경이 필요하면 먼저 변경 이유를 설명한다. 실행 권한은 [AI 협업 규칙](ai-collaboration.md)을 따른다.
- 기존 외부 계약의 호환성을 고려한다.
- 여러 모듈에 영향을 주는 변경은 영향 범위를 분석한다.
- 팀에서 정하지 않은 아키텍처를 절대 규칙처럼 적용하지 않는다.

## Team Decision Needed

- 계층 또는 모듈 구조
- 계층별 책임
- 의존성 방향
- Domain Logic 위치
- Transaction 경계
- DTO 및 Persistence Model 사용 기준
- 외부 시스템 접근 기준
- 공통 예외 처리
- 데이터 정합성 유지 방법

모든 항목은 아직 미결정이다. 현재는 특정 계층 구조나 디자인 패턴을 강제하지 않는다. 팀이 결정한 내용을 이 문서에 반영한 후 적용한다.
