# Code Review Workflow

먼저 [AI 협업 규칙](../rules/ai-collaboration.md), [코드 규칙](../rules/code.md), [아키텍처 규칙](../rules/architecture.md), [테스트 규칙](../rules/testing.md)을 읽는다.

## Step 1. 변경 범위 분석

Base / Target Branch, 변경된 파일, Commit, 전체 Diff, 변경 목적을 확인한다. 비교 대상을 근거 없이 추측하지 않는다. 저장소가 없거나 비교 대상이 불명확하면 필요한 정보를 요청하고 확인 가능한 범위와 한계를 보고한다.

Branch 리뷰에서는 확인된 Target을 기준으로 `git log <target>..HEAD --oneline`, `git diff <target>...HEAD`를 사용할 수 있다. `<target>`은 실제 참조로 대체한다. 미커밋 변경 리뷰라면 `git diff`, `git diff --staged`와 관련 미추적 파일의 실제 내용을 확인한다. MR 리뷰라면 해당 MR의 Source/Target과 실제 Diff를 확인한다.

변경된 줄뿐 아니라 관련 호출부·계약·테스트를 읽는다. 전체 맥락 없이 일부 코드만으로 단정하지 않는다.

## Step 2. Correctness

해당 기술과 변경사항에 관련된 경우 다음을 우선 확인한다.

- 잘못된 조건문, null 또는 빈 값 처리
- 예외 처리 누락, 상태 변경 오류, 잘못된 데이터 처리
- 데이터 정합성, 동시성 문제, Transaction 문제

## Step 3. Architecture

아키텍처 규칙을 기준으로 책임 분리, 의존성 방향, 불필요한 결합, 중복된 책임, 기존 설계 원칙 위반을 확인한다. 프로젝트에서 확정하지 않은 아키텍처를 강요하지 않는다.

## Step 4. Database

DB 관련 변경이 있을 때만 N+1, 불필요한 Query, Index, Transaction 범위, Lock 범위, 대량 데이터 처리를 확인한다. 실제 근거 없는 성능 문제를 단정하지 않는다.

## Step 5. Security

보안에 관련된 변경과 영향을 확인한다. 인증, 인가, 입력 검증, Injection, 민감정보 노출, 권한 우회 가능성을 점검한다.

## Step 6. Testing

변경사항을 검증하는 테스트 존재 여부, 정상 경로, 실패 경로, 경계값, 기존 동작 영향, 필요한 회귀 테스트를 확인한다. 실행 가능한 환경과 권한이 있으면 관련 테스트를 실행한다. 실행한 명령·결과와 실행하지 못한 검증을 구분한다.

## Step 7. Convention

코드 규칙과 확정된 프로젝트 컨벤션을 적용한다. Formatter나 Linter가 검출할 수 있는 단순 스타일 문제는 우선순위를 낮춘다.

## Step 8. Review Output

| Severity | 기준 | 처리 |
| --- | --- | --- |
| Critical | 데이터 손실, 심각한 보안 문제, 서비스 중단 가능성, 치명적인 정합성 문제 | 반드시 수정 대상으로 보고 |
| Major | 실제 버그 가능성이 높은 문제, 중요한 설계 규칙 위반, 검증이 필요한 주요 결함 | 수정 또는 명시적인 검토 필요 |
| Minor | 유지보수성·가독성 개선, 성능 최적화 제안 | 개선 제안으로 구분 |

문제는 Critical, Major, Minor 순서로 보고한다. 각 항목에는 다음을 포함한다.

- Severity
- 파일 및 코드 위치: 확인한 경로와 줄 번호, 줄 번호를 확인할 수 없으면 심볼 등 실제 위치 정보
- 문제 내용
- 실제 문제가 발생할 수 있는 구체적인 조건과 근거
- 수정 방향

문제를 억지로 만들어내지 않는다. 실제 코드로 뒷받침할 수 있는 문제를 우선하고, 추측을 확정적인 문제로 표현하지 않는다. 단순 취향 차이를 오류처럼 지적하지 않는다.

발견한 문제가 없으면 그렇게 보고하되, 확인한 범위와 검증 한계를 함께 명시한다. 검토하지 못한 범위까지 안전하다고 보증하지 않는다. 실제 실행한 검증과 미해결 질문도 보고한다.

리뷰 요청만으로 코드를 수정하거나 원격 리뷰 댓글을 게시하지 않는다. 자동 리뷰가 통과했다고 사람이 승인한 것으로 처리하지 않는다.
