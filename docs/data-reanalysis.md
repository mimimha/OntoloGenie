# 변경 데이터 재분석 (S15P31C106-121)

FN-AIP-06. `feature/121-data-reanalysis`에서 구현했다. 2026-11-07 수동 수집 화면(120)이 병합된 최신 develop `0579f19`를 충돌 없이 반영했다.

## 확인한 계약

- [018 원문](https://app.notion.com/p/405bdf14d2d881128b30ebe8700524f8)과 [운영 Swagger](https://ontologenie.com/swagger-ui/index.html)의 018·019 제공 상태 및 018 요청/응답을 확인했다.
- `runKind=REANALYSIS`와 `targets[].sourceResourceId`, 선택 `targets[].columns`로 요청한다. 변경 구간 changeSeqFrom/changeSeqTo는 받지 않는다. 선택한 테이블의 현재 데이터를 다시 분석하며 변경 행만 자동 추적하는 UI는 제공하지 않는다.
- 같은 대상·컬럼 집합의 QUEUED/RUNNING 분석이 있으면 joined=true와 기존 ID가 온다. 기존 실행이 INITIAL일 수도 있으므로 요청한 종류로 덮어쓰지 않는다.
- 019의 targets는 자원 ID만 포함한다. 선택 컬럼은 `analysisRange.columns`에서 표시한다. 기존 확정 내용은 재분석 접수만으로 변경되지 않으며 후보는 기존 검토 흐름에서 확인한다.

## 구현

연결 규칙의 AI 분석 영역에 변경 데이터 재분석 진입을 추가했다. 기존 대상 선택을 재사용해 테이블·컬럼을 고르고 원천·자료명·선택 컬럼 요약을 확인한 뒤 요청한다. 진행·결과·실패 사유·후보 조회는 기존 019·020 흐름을 사용한다. 최근 실행 목록에서 최초 분석/재분석을 구분한다.

수동 접수는 자동 재시도하지 않고 연속 클릭을 차단한다. 상태 조회 오류 시 자동 폴링을 멈추고 명시적인 조회 재시도를 제공한다. API·DB·인증 구조는 변경하지 않았다.

## 남은 확인

- 운영 재분석은 실행하지 않았다. 실제 AI 결과·실제 서버 권한/합류/충돌 검증, 팀원 리뷰 및 병합 후 확인은 남아 있다.
