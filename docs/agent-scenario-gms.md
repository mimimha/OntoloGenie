# Agent 시나리오 GMS 시험 (S15P31C106-342)

가상 프레스 데이터를 시험 DB에 넣고, 실제 GMS 모델로 Agent가 시나리오 질문에 필요한 객체를 찾아 조회하는지 본다.

- 시험: `backend/src/test/java/com/axcore/platform/agent/service/AgentScenarioGmsTests.java`
- 적재기: 같은 폴더의 `AgentScenarioDataset.java`
- 시험 데이터: `backend/src/test/resources/agent-scenario/press-v1.0.json.gz` (341, 만드는 법은 같은 폴더 `README.md`)
- 정답: `ai/data/gold-v1.0/scenario_answers.json`

## 언제 도는가

- 클래스에 `AXCORE_AGENT_LLM=openai` 조건을 걸었다. 이 값이 없으면 클래스 전체를 건너뛴다.
- 건너뛸 때는 Spring 컨텍스트를 띄우지 않으므로 시험 데이터도 넣지 않는다.
- 그래서 CI(`./gradlew build`)에서는 돌지 않는다.
- 켜면 이 클래스만 쓰는 시험 DB(Testcontainers)를 새로 만들어 넣는다. 다른 시험의 DB와 섞이지 않는다.

## 실행 방법

`backend/`에서 실행한다. GMS 키(`AXCORE_AGENT_LLM_API_KEY`)가 환경 변수에 있어야 한다. 키를 명령이나 파일에 적지 않는다.

```bash
AXCORE_AGENT_LLM=openai ./gradlew test --rerun --tests "com.axcore.platform.agent.service.AgentScenarioGmsTests"
```

PowerShell은 다음처럼 한다.

```powershell
$env:AXCORE_AGENT_LLM='openai'; ./gradlew test --rerun --tests "com.axcore.platform.agent.service.AgentScenarioGmsTests"
```

- 시나리오 하나만 돌리려면 `--tests` 끝에 메서드 이름을 붙인다. 예: `...AgentScenarioGmsTests.s3*`
- 결과는 `backend/build/test-results/test/TEST-com.axcore.platform.agent.service.AgentScenarioGmsTests.xml`의 로그에 남는다. `GMS 시나리오`로 시작하는 줄을 본다.

## GMS 크레딧 주의

- `--rerun`을 빼면 Gradle이 앞 결과를 재사용해 시험을 건너뛸 수 있다. 환경 변수는 Gradle이 바뀐 입력으로 보지 않으므로, 스위치 없이 build한 뒤 처음 켜서 돌릴 때도 `--rerun`이 필요하다. 붙이면 매번 GMS를 부른다.
- 한 번 다 돌리면 지금은 질문을 9번 한다(S3는 기간을 되물어 2번, P1·P2·P3·S4·L1·L2·L3은 1번). 서버가 대상을 되묻게 되면 P1·P2·S4가 1번씩 늘어 최대 12번이다. S3는 되묻기 답에 설비와 기간을 함께 말하므로 그대로 2번이다.
- 질문마다 질문 해석 AI를 1번 부르고, 되묻지 않으면 답변 AI를 도구 호출 횟수만큼 더 부른다.
- 필요한 시나리오만 골라 돌린다. 반복 실행이 필요하면 팀과 크레딧을 먼저 확인한다.

## 흐름

답변 처리기(`AgentAnswerProcessor`)가 한 질문을 처리하는 순서를 시험에 옮겼다. 처리기는 비동기 이벤트로만 돌아 시험에서 직접 부를 수 없다. 처리기 순서가 바뀌면 시험의 `turn`도 함께 바꾼다.

1. 질문 해석 AI가 목적·대상·기간을 뽑는다.
2. 서버가 대상을 객체로 정한다. 정하지 못하거나 조건이 빠지면 되묻는다.
3. 되물으면 시험이 사용자처럼 한 번 답한다(2턴). 후보 중 설비를 고르고, 필요하면 기간을 말한다.
4. 정했으면 그 객체를 허용하고 답변 AI가 조회 도구를 부른다. Action 도구는 빼서 계획이 만들어지지 않게 한다.
