# S15P31C106-229 변환 미리보기

관리자 → 데이터 연결 → 원천 선택 → 원천 매핑 → 객체 매핑 등록/편집.
속성 변환은 객체 매핑 상세 → 속성 매핑 등록/편집 안의 변환 미리보기에서 확인한다.

## 현재 범위

- 040 요청·102 결과 API는 2026-11-07 운영 Swagger와 현재 backend Controller에 없다. 실제 어댑터를 주입하지 않으며 배포 후에도 미리보기 요청은 비활성화된다.
- 편집 중인 키·속성·변환 초안을 사용한다. 미리보기 버튼은 기존 저장 API를 호출하지 않는다.
- 미리보기 행 수 입력의 Enter 기본 제출을 차단한다. 객체·속성 편집에서 실제 저장은 기존 저장 버튼으로 실행한다.
- 기존 속성 매핑은 모든 페이지를 읽고 현재 편집 항목을 대체하거나 새 초안을 추가한다. 일부 페이지만으로 시험 변환하지 않는다.
- 입력한 초안이 바뀌면 이전 결과와 진행 상태를 제거한다. 늦은 응답도 표시하지 않으며 창을 닫은 뒤 초안 준비가 끝나도 요청하지 않는다.
- 접수·대기·실행·성공·실패, joined 안내, 만료·404, 조회만 재시도, 변환 전후 값과 행별 오류(행·속성·단계·코드·근거)를 표시한다.
- 화면 입력은 1~20행(기본 20)으로 제한한다. 040 실제 한도·기본값은 계약 확정 시 함께 확인한다.
- `previewModel.ts`는 화면 전용 모델이며 서버 DTO나 정책을 정의하지 않는다. 표본은 컴포넌트 안에만 보관하며 Query 캐시·브라우저 저장소에 넣지 않는다.
- 원천 오류 원문은 표시하지 않는다. 가림 셀에는 원문을 전달하지 않는다. 변환 엔진을 프론트에서 구현하거나 결과를 추정하지 않는다.
- 기존 화면이 지원하지 않는 행 조건/문서 경로의 편집 제한은 유지한다.

## 확인한 명세

- [040 객체 매핑 시험 변환](https://app.notion.com/p/405bdf14d2d8816bbd89e4d25e4783dd): POST `/api/v1/ontology/source-resources/{id}/mapping-previews`, 저장 전 초안으로 시험 변환, 배치 접수(202 previewId), 업무 객체·연결·매핑 저장 없음, 동일 초안·행 수의 진행 요청 joined, 만료 1시간.
- [102 원천 미리보기 결과 조회](https://app.notion.com/p/406bdf14d2d8817fa984ccd997fb1d8b): GET `/api/v1/ontology/source-previews/{previewId}`, 상태와 MAPPING_PREVIEW의 objects[]·rowErrors[], 만료/삭제 404.
- Jira 229는 변환 전후·실패 근거 표시를 요구한다. 102 초안에는 변환 전 값·행과 객체의 대응·단계별 근거 필드가 구체적으로 없어 실제 DTO를 확인해야 한다.

## API 제공 후 할 일

1. BE S15P31C106-185 담당자(이주헌)와 040·102 요청/결과 DTO, 행 수 한도, 초안 검증·오류 형식·중복 처리·만료 규칙을 확인한다.
2. 225와 공유하는 102의 민감값 표시 정책을 확정한다. 허용된 값·정제한 근거만 화면 모델에 전달하며 금지 컬럼·원문·SQL이 오류나 DOM에 나오지 않게 한다.
3. 변환 전 값과 행별 대응 정보가 없으면 `unavailable`로 표시한다. 원천 표본을 별도 조회해 서로 다른 행을 임의로 결합하지 않는다. 전후 비교 완료 기준을 충족하려면 백엔드 근거 제공이 필요하다.
4. 확정 DTO를 화면 모델로 바꾸는 어댑터를 작성하고 `MappingPanel`의 `previewAccess`에 주입한다. UI 모델 필드가 서버 계약에 존재한다고 가정하지 않는다.
5. 실제 초안 요청 → 대기/실행 → 객체·행별 오류, 권한·충돌·joined·만료·가림 정책, 업무 데이터가 저장되지 않는 것을 검증한다.
6. 팀원 리뷰·MR 병합·병합 후 확인까지 완료 기준을 점검한다. API 연결 및 운영 검증 전에는 Jira를 완료 처리하지 않는다.

API·DB·인증 구조 변경 없음. 실제 API 연동·운영 시험 변환은 미완료다.
