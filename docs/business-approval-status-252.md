# 현업 승인 후 적용 상태 화면 (252)

## 승인된 구현 범위

- Jira: [S15P31C106-252](https://ssafy.atlassian.net/browse/S15P31C106-252), 기능 `FN-REV-08`.
- 원래 Jira와 기능 명세는 추후·보류다. 사용자가 이번 작업을 **상태 화면만 우선 구현**하도록 명시했다. 승인 주체·절차·실행 정책은 확정하지 않는다.
- 진입: **연결 규칙 → 검토 제안 → 제안 상세 → 이력 → 현업 승인 상태**. 주소는 `/admin/rules/{proposalId}/history?view=business`다. 상단의 정의·규칙 이력(`/admin/history`)과는 다른 화면이다.
- 승인 요청, 대기·현재 상태, 현업 결정 기록, 실제 적용 상태를 각각 표시한다. 기존 제안의 승인·반영 상태 탭은 그대로 사용한다.
- 승인 요청·현업 결정·적용 실행 버튼은 항상 비활성이다. 해당 실행 폼과 API 연동은 이번 범위에 포함하지 않는다.

## 현재 운영 연결 상태

현업 승인 조회 API 번호·경로·응답 계약은 미정이다. 프로덕션에는 조회 어댑터를 연결하지 않았으며 새 HTTP 요청도 만들지 않았다. 화면은 준비 중 안내와 네 항목의 **미확인**을 표시한다. API 미연결을 미요청·미적용·승인 완료로 해석하지 않는다.

`BusinessApprovalSource.load(proposalId, revision, signal)`은 조회를 주입하는 프론트 인터페이스다. `businessApproval.ts`의 상태 이름과 자료형은 테스트 및 표시를 위한 내부 모델이며 백엔드 API 계약이나 확정된 업무 절차가 아니다. 실제 API가 제공되면 별도의 조회 어댑터에서 확정된 DTO를 이 모델로 변환하고 연결해야 한다.

기존 백엔드 `ProposalDecisionService`는 관리자 `APPROVE`에서 즉시 적용한다. 그 결과나 기존 `applyStatus`를 현업 승인으로 간주하지 않는다. 해당 승인 로직·인가·DB·API는 변경하지 않았다.

## 상태 표시 및 조회 처리

- 응답의 제안 ID와 개정이 현재 대상과 일치하고 필수 구조가 유효할 때만 표시한다.
- 요청 번호·요청자·시각·사유, 결정별 결정자·시각·사유, 적용 상태·적용자·시각·실패 사유를 표시한다. 결정 기록은 전달받은 순서를 보존한다.
- 제공되지 않은 기록은 미제공으로 표시한다. `NOT_REQUESTED`가 명시된 경우에만 미요청으로 표시한다. 알 수 없는 상태는 원래 값과 함께 알 수 없는 상태로 표시한다.
- 현업 승인과 실제 적용 완료를 구분한다. 승인 기록만으로 적용 완료를 표시하지 않는다.
- 로딩·재조회·오류 중에는 이전 상태를 숨긴다. 중복 조회를 막고 대상·개정 변경 시 기존 조회를 취소한다. 자동 재시도는 하지 않는다.
- 권한·인증·대상 없음 등 오류에는 재시도를 제공하지 않는다. 서버·네트워크·응답 형식 오류는 수동 재조회할 수 있다. 조회 오류의 원문은 사용자 화면에 그대로 노출하지 않는다.

## 백엔드 251 담당자에게 확인할 내용

[S15P31C106-251](https://ssafy.atlassian.net/browse/S15P31C106-251)의 담당자는 정유림이다. 다음 내용 확정 후 조회 API부터 연결한다.

1. **승인 주체와 권한:** 요청 가능자·현업 승인자·적용 실행자의 역할, 본인 승인 허용 여부, 다수 승인 필요 여부, 조회 가능한 사용자 범위.
2. **상태와 전이:** 요청·대기·승인·반려·취소·재요청·적용 중·완료·실패의 실제 상태값과 허용 전이. 승인 후 자동 적용인지 별도 실행인지.
3. **기존 승인과 관계:** 관리자 `APPROVE` 즉시 적용과 현업 승인 후 적용의 대상·구분 조건·책임. 기존 흐름의 대체 여부를 팀에서 결정해야 한다.
4. **대상과 개정:** 승인의 제안·개정 연결 방식, 개정 또는 검사 결과 변경 시 승인 유효성 및 재승인 여부.
5. **조회 계약:** API 번호·경로, 제안 ID·개정, 요청 식별자·요청자·시각·사유, 결정 목록·순서·페이지 처리, 결정자·결정·시각·사유, 적용 상태·담당자·시각·실패 사유, 값 미제공의 의미와 오류 코드.
6. **후속 실행 계약:** 이번 화면에서는 실행하지 않는다. 추후 요청·결정·적용 API를 만들 때 중복 방지·최신 개정 충돌·승인 유효성·감사 기록·적용 원자성을 함께 확정해야 한다.

## 남은 작업과 완료 조건

- 백엔드 업무 절차 및 API 제공 후 조회 어댑터와 상태 매핑을 연결한다.
- 실행 기능은 별도 범위 확정 후 폼·권한별 동작·충돌 처리·실행 API를 구현한다. 현재 비활성 버튼만으로 실행 기능이 구현됐다고 보지 않는다.
- 실제 백엔드 및 운영에서 요청→대기→결정→적용 상태와 조회 권한·오류를 검증한다. 현재 자동 테스트는 주입된 검증 데이터로 실행하며 실제 업무 승인이나 운영 반영 검증을 대신하지 않는다.
- 팀원 리뷰·MR 병합·후속 연동 및 검증이 끝나기 전에는 Jira 전체를 완료 처리하지 않는다. 현재 기록은 상태 화면 준비 범위와 잔여 작업을 구분하기 위해 유지한다.
