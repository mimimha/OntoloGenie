# 수동 수집과 실행 이력 화면 (S15P31C106-120)

## 확인한 계약과 제공 상태

2026-11-11 원격 develop `41da6ee`의 Controller·DTO·서비스·API 테스트와 Chrome에서 아래 Notion 원문을 대조했다. 073·074·075는 develop에 구현되어 있으며 이 변경에서 기존 화면에 실제 HTTP 어댑터를 연결했다. 운영 배포 버전·실제 수집 성공 여부와 저장소 구현 여부는 구분한다.

- [073 원천 데이터 수동 수집 요청](https://app.notion.com/p/405bdf14d2d881c1ae77f61a7fdb01f9): POST /api/v1/sources/{id}/sync-runs, 선택 sourceResourceIds, 202 접수.
- [074 원천 수집 이력 조회](https://app.notion.com/p/405bdf14d2d881e9a77bed57b622c906): GET 같은 경로, status·triggerKind·from·to·page·size. 기본은 CDC 제외이며 meta.cdcLastAppliedAt을 표시한다.
- [075 수집 상태·건수·실패 사유](https://app.notion.com/p/405bdf14d2d88116b743f0525b5038ad): GET /api/v1/sync-runs/{id}, 실행 상태와 테이블별 방식·건수·오류.

## 구현과 연결 경계

데이터 연결의 수집 이력 탭에 전체 또는 선택 테이블 수동 요청, 접수 결과, 기존 실행 합류 안내, 상태·원인·기간 필터, 페이지 이동, 상세·테이블별 결과를 구현했다. 조회 중·빈 결과·오류를 분리한다. 날짜 범위는 시작 포함·종료 미포함이며 사용자의 현지 시각을 ISO 시각으로 변환한다.

중복 여부는 테이블별 서버 응답을 따른다. 원천에 실행 중 작업이 있다는 이유로 다른 테이블 요청까지 막지 않는다. 전체 합류 시 최상위 syncRunId=null을 처리하고 resources[].syncRunId 각각을 열 수 있다. 수동 요청의 연속 클릭은 차단하며 자동 재시도하지 않는다. 실행 상세·목록은 대기/실행 중인 경우 2초 간격으로 조회하고 오류 시 자동 조회를 멈춘다. 테이블 상태가 QUEUED여도 실행이 끝날 수 있으므로 진행 여부는 실행 상태로 판단한다.

SourcesPage가 SourceSyncRuns에 sourceSyncApi를 전달해 073·074·075를 호출한다. 공통 API 클라이언트의 세션·CSRF 처리를 사용하며 요청을 자동 재시도하지 않는다. null·빈 접수 응답은 성공으로 표시하지 않는다. 권한은 기존 ADMIN 관리 라우트로 제한하며 실제 서버 인가는 별도로 검증해야 한다.

테이블 이름은 014 원천 자원 목록과 ID로 대응하며, 목록에 없는 ID는 `테이블 #ID`로 표시한다. 접수 결과·실행 상세와 400·422·409의 `details.ids`에 적용한다. `409 + recoveryReason=SOURCE_CHANGED`에는 CDC 재연결 후 재시도를 안내한다. 서버의 거절 응답과 접수 여부가 불확실한 네트워크·서버·응답 해석 실패를 구분한다. 073의 `resources[].syncStrategy`는 11-11 명세와 백엔드에 추가되어 현재 타입을 유지한다.

`meta.cdcLastAppliedAt`은 마지막으로 반영한 원천 트랜잭션의 원천 커밋 시각이다. CDC 소비 기록이 없어 필드가 생략되거나 null이면 `—`로 표시한다. 변경이 없거나 복구 중에는 이전 시각이 유지될 수 있으므로 현재 반영 지연 시간으로 해석하지 않는다.

## 남은 실제 환경 검증

1. 운영 Swagger·배포 버전과 실제 073·074·075 응답을 대조한다.
2. 검증 가능한 테이블·활성 매핑을 준비한 환경에서 전체·부분 합류, 여러 기존 실행, 403·404·409·422, QUEUED→RUNNING→성공/실패, CDC 필터·마지막 반영 시각, 페이지·기간을 검증한다.
3. 팀원 리뷰와 MR 병합 후 동작 확인을 완료한다. Jira의 기존 완료 상태는 변경하지 않았다.

API·DB 계약은 변경하지 않았다. 프론트 테스트는 모의 HTTP 응답 기반이며 실제 수집 성공 증거를 대신하지 않는다.

## 자동 검증 범위

- SourcesPage에서 실제 어댑터를 통한 요청·이력 갱신·상세 결과 연결.
- 전체·선택 요청, 연속 클릭 중복 접수 방지, 부분·전체 합류와 테이블별 실행 링크.
- 실행이 RUNNING이고 테이블은 QUEUED인 경우의 진행 표시와 완료·실패 조회.
- 400·401·403·404·409·422, 문제 테이블 이름·ID, 재연결 안내, 네트워크 실패와 null 응답.
- 상태·원인·기간·페이지 조회 조건, 빈 이력·조회 실패·재조회.
- 비관리자 3개 역할의 수집 탭 직접 진입 차단과 073~075 미호출.

자동 테스트·정적 검사·빌드의 최종 실행 결과는 MR에 기록한다. 실제 수집 요청은 실행하지 않았으며 모의 응답 테스트를 운영 검증으로 보지 않는다.
