# Agent 대화 문맥 유지 범위 비교 실험 (334)

질문 해석 AI에 넘기는 최근 대화 원문을 몇 턴·몇 토큰까지 둘지 실제 모델 호출 결과로 비교한다. 147 2단계의 기본값(`axcore.agent.history.max-turns` 4, `max-tokens` 2000)을 정하는 근거다. 정책은 [Agent 답변 정책](agent-response-policy.md) 3.6을 따른다.

## 1. 방법

- 모델: gpt-5.6-sol (GMS chat/completions), 2026-11-11 실행
- 대상: 질문 해석 AI(`QuestionInterpreter`)만 부른다. 최근 대화 원문은 해석 AI에만 넘기므로 답변 AI와 조회 도구는 부르지 않는다.
- 조합: 최근 턴 수 2·4·8 × 토큰 상한 1000·2000·4000 = 9개, 비교 기준으로 원문을 넘기지 않는 경우(원문 없음) 1개
- 질문 세트: 1차 24개, 질문마다 3번 반복 → 조합마다 72회, 모두 720회 호출. 2차는 10개를 더해 34개(2절 2차)
  - 질문마다 앞선 대화 8턴(설비 8대에 대해 비가동·정비·금형·가동률·불량률·작업지시·재배정·실행 이력을 한 번씩 물음)과 직전 답변의 조건이 있다.
  - 후속 질문이 가리키는 대상이 몇 턴 전에 나왔는지(1·3·5·7턴 전, 2차에서 2·4턴 전 추가) 각 5개. 예: "정비 일정 물어봤던 그 설비 지난달 불량률은?"
  - 앞 대화와 관계없는 질문 4개. 새 설비를 묻거나 "전체 설비"처럼 종류 전체를 묻는다. 옛 대상을 끌어오면 오답이다.
  - 답변은 실제 답변처럼 한 턴에 질문과 답변을 합쳐 213~318자(평균 251자)로 맞췄다.
- 채점: 해석 결과를 답변 처리기처럼 직전 답변의 조건에 이어 붙인 최종 대상이 정답과 같으면 맞다. 정답에 기간이 있으면 기간도 같아야 한다. "이번 달"은 오늘(11/11)까지와 월말(11/30)까지를 모두 맞다고 본다.
- 입력 토큰: 모델 응답의 `usage.promptTokens`. 지시문과 출력 형식 안내를 포함한 해석 요청 전체다.
- 다시 돌리는 법: `AXCORE_AGENT_LLM=openai`, GMS 키, `AXCORE_AGENT_EVAL=context`를 넣고(조합만 고르려면 `AXCORE_AGENT_EVAL_COMBOS=0:0,2:2000,3:2000,4:2000`) `./gradlew test --rerun --tests "com.axcore.platform.agent.service.ContextWindowExperimentGmsTests"`. 결과는 `backend/build/agent-eval/`에 표(.md)와 호출별 CSV로 남는다. 질문 세트는 `backend/src/test/resources/agent-eval/context-window-scenarios.json`이다.

## 3. 해석

- 정답 여부는 가리킨 턴이 넘겨준 원문 안에 들어 있는가로 갈렸다. 원문 안에 있으면 모든 조합에서 맞혔고, 밖에 있으면 모두 틀렸다. 모델의 이해력보다 유지 범위가 결과를 정한다.
- 1턴 전(직전 답변의 대상)은 원문 없이도 맞혔다. 직전 답변의 조건을 따로 넘기기 때문이다(147 1단계).
- 원문을 넘겨도 관계없는 새 질문에 옛 대상을 끌어온 경우는 없었다.
- 토큰 상한이 턴 수보다 먼저 걸린다. 상한 1000이면 4턴·8턴을 정해도 3턴만, 2000이면 8턴을 정해도 6턴만 들어갔다.
- 지금 상한은 글자 수로 어림한다(정책 3.6). 이번 질문 세트에서 한 턴은 어림값 약 290(태그 45 포함)인데 실제 입력 토큰은 약 170~180이었다. 한국어 답변에서는 어림값이 실제보다 1.6배쯤 크다. 그래서 상한 4000(어림)은 실제로 약 2,500토큰 이내다.
- 한 턴을 더할 때마다 해석 요청의 입력 토큰이 약 175씩 늘었다(원문 없음 1,233 → 2턴 1,585 → 3턴 1,758 → 4턴 1,929 → 8턴 2,606).
- 그래서 턴 수를 정하는 일은 "사용자가 몇 턴 전까지 가리키는 것을 받아 줄지"와 "턴 하나에 약 175토큰"을 맞바꾸는 일이다. 모델은 넘겨받은 범위 안이면 맞히므로, 범위를 넓힐수록 정확도는 오르지만 토큰도 같은 비율로 는다.
- 아주 오래전 대화까지 원문으로 넘기는 것(16턴, 100턴)은 토큰이 턴 수만큼 늘어 맞지 않다. 오래된 대화를 원문 대신 요약으로 넘길지와 그 범위는 333(오래된 대화 요약)에서 정한다.
- 상한은 평소 양이 아니라 답변이 유난히 길 때 막는 안전장치다. 이번 세트에서 상한 1000은 4턴도 다 못 넣었고(3턴만 들어감), 2000은 4턴을 자르지 않았다. 4000은 결과가 2000과 같았지만 긴 답변이 몰릴 때 최대 크기가 두 배다.

## 4. 기본값 선택지

**결정 (2026-11-11, 담당 장민화): 4턴·2000 유지.** 토큰을 아끼는 것을 우선해 4턴 전까지만 원문으로 받고, 그보다 오래된 대화는 333(오래된 대화 요약)에서 다룬다. 설정 기본값은 바꾸지 않는다. MR에서 담당자 외 팀원 검토를 받는다.

| 안 | 맞히는 범위 | 해석 요청 입력 토큰(평균) | 원문 없음 대비 |
|---|---|---|---|
| 2턴·2000 | 2턴 전까지 | 1,585 | +약 350 |
| 3턴·2000 | 3턴 전까지 | 1,758 | +약 525 |
| 4턴·2000 (지금) | 4턴 전까지 | 1,929 | +약 700 |
| 8턴·4000 | 7턴 전까지 | 2,606 | +약 1,370 |

- 1턴 전(직전 답변의 대상)은 원문 없이도 맞히므로, 원문은 2턴 전부터 쓸모가 있다.
- 토큰을 아끼는 것이 우선이면 2~4턴 중에서 고르고, 그보다 앞은 333 요약으로 넘기는 것을 제안한다. 상한은 2000을 그대로 둔다.
- 값을 바꾸면 `backend/src/main/resources/application-api.yml`의 기본값, `RecentTurns`의 `@Value` 기본값, 정책 문서 3.6의 숫자를 함께 바꾼다.

## 5. 한계와 함께 본 것

- 배포 뒤 실제 데이터와 실제 대화로 배포 사이트에서 다시 확인한다(담당 장민화).
- 질문 세트는 직접 만든 가상 대화다. 실제 사용자가 몇 턴 전을 얼마나 자주 가리키는지는 반영하지 않았다. 거리별로 같은 수를 넣었으므로 전체 정답률보다 거리별 정답률을 기준으로 본다.
- 실제 답변은 표나 목록이 들어가 이번 세트보다 길 수 있다. 그 경우 같은 상한에 들어가는 턴 수가 줄어든다.
- gpt-5.6-sol만 확인했다.
- 1차는 두 번 실행했다. 첫 실행은 "이번 달"의 끝을 오늘(11/11)만 정답으로 채점했고, 아래 이유로 월말(11/30)도 정답으로 바꾼 뒤 같은 질문 세트로 다시 실행했다. 2절 1차 표와 "모두 720회 호출", "같은 질문을 3번 반복했을 때 정답 여부는 모든 조합에서 같았다"는 두 번째 실행 결과다. 첫 실행과 다른 것은 이 기간 채점뿐이며, 대상 정답 여부는 두 실행이 같았다(720회 모두).
- 두 실행 모두 "이번 달"을 11/01~11/30(월말까지)으로 읽은 답이 있었다(첫 실행 720회 중 57회). 앞 대화에 "이번 달(11/01~11/11)" 답변이 있으면 오늘까지로 읽었다. 해석 지시에 "이번 달"의 끝을 정하지 않아서이며, 이 실험 범위 밖이라 채점에서 둘 다 맞다고 봤다. 어느 쪽으로 할지는 따로 정해야 한다.
