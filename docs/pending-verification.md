# 후속 연동·검증 목록

작업 중 API·데이터가 준비됐는지 확인하고, 검증한 항목만 완료로 바꾼다. 화면 구현·모의 테스트 통과를 실제 서버 연동 완료로 취급하지 않는다.

| 이슈             | 남은 항목                                                                  | 다시 확인할 조건                                                 |
| ---------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 110              | 실제 제안의 상세·근거·신뢰도·필터·페이지 이동                              | 서버에 실제 제안 및 페이지 이동할 만큼의 데이터 등록             |
| 111              | 실제 관계·속성으로 저장, 개정 증가·검사 요청·변환 순서 보존                | 실제 관계·속성과 검사용 제안 준비                                |
| 112              | 서버 후보 비교, 선택·보류 저장, 후보별 검사 결과                           | 실제 복수 후보 등록, 선택·보류 API 및 후보별 검사 연결 계약 제공 |

## 확인된 진행 상태

- 116: API 055 결정 이력·현재 반영 상태 화면 작업. 056·057 개별 보류 건 목록·상세 API가 최신 백엔드에 추가됐음을 확인했다. 해당 화면의 목업 위치 확인 후 UI를 연결하고, 실제 결정·보류 데이터로 서버 조회를 검증해야 한다. 승인·보류·거절 저장 API 054와 조회 이력을 구분한다.

- 115: 검토 사유·결정 버튼 선행 화면 작업. API 054의 실제 결정 저장·반영·감사·충돌·중복 요청·개별 건 보류와 선택지 전달은 131 제공 후 연결해야 한다. API 055 이력 조회가 제공돼도 결정 저장 완료를 뜻하지 않는다.

- 104 역할별 접근·226 계정 관리는 사용자 서버 검증 완료.
- 112 비교 화면 첫 MR 병합, 자동 테스트·사용자 로컬 검증 완료. 서버 목록 0건으로 상세 검증은 보류.
- 113: 059~061 제공을 확인하고 `/admin/checks`에 실행 목록·수동 검사·상태 조회를 연결했다. 062는 완료된 실행의 규칙별 결과를 페이지로 읽는다. 전체 또는 046으로 찾은 ACTIVE 규칙을 검사하며, 후보 ID를 MANUAL로 보내지 않는다. MSW 화면·API·권한 테스트와 로컬 데모를 검증했으며 실제 서버의 접수·배치·집계 저장은 미검증이다. 자세한 흐름은 `docs/check-run.md`의 프론트 수동 검사 연동 절을 따른다.
- 227은 사용자 결정으로 범위 제외·Jira 삭제, 초안 삭제 완료.

이 목록은 배경 감시나 자동 알림을 설정한 것이 아니다. 후속 작업 시 확인하는 체크리스트다.
