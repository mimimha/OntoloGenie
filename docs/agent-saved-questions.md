# 내 질문 저장 확인 (S15P31C106-257)

기존 1단계 구현은 자주 쓰는 질문을 이 브라우저에 계정별로 보관한다. 이번 작업에서는 저장 실패를 성공으로 표시하던 부분과 저장 복구 처리를 보완했다. 서버 저장이나 기기 간 동기화는 포함하지 않는다.

## 사용과 저장 범위

- 입력한 문장을 `내 질문 저장`으로 보관한다. 빈 문장과 중복은 제외하고, 계정당 최대 10개·질문당 최대 2,000자다.
- 저장한 질문을 누르면 입력란에 채워져 수정 후 전송할 수 있다. 선택만으로 전송하지 않는다.
- 각 질문의 지우기 버튼으로 삭제한다. 다른 계정으로 전환하면 해당 계정의 목록을 읽는다.
- 같은 브라우저에서 화면을 다시 열어도 남는다. 다른 PC·브라우저에서는 공유되지 않고, 브라우저 저장 공간을 지우면 사라진다.
- 저장 버튼의 설명에 브라우저·계정별 저장 범위를 표시한다.

## 저장 실패와 복구

- 브라우저 저장이 실패하면 `임시 보관 중`과 현재 화면에서만 유지된다는 안내를 표시한다. 새로고침하면 변경 내용이 사라지거나 이전 내용으로 돌아갈 수 있다.
- 실패한 추가·삭제는 현재 화면에서 사용할 수 있다. 다음 추가·삭제 때 저장을 다시 시도하며, 성공하면 실패했던 변경도 함께 반영한다.
- 저장할 때마다 최신 저장소를 읽고 실패했던 변경을 순서대로 적용해 다른 탭의 질문을 처음 읽었던 목록으로 덮지 않는다. 탭의 변경을 실시간 표시하는 기능이나 동시 쓰기 잠금은 없다.
- 복구할 때는 모든 추가·삭제를 반영한 뒤 10개 한도를 검사한다. 다른 탭의 질문과 합친 최종 목록이 한도를 넘으면 저장소를 덮거나 임시 질문을 버리지 않고, 질문을 더 지우도록 안내한다. 공간을 확보하면 임시 질문까지 저장한다.
- 계정이 바뀌면 이전 계정의 임시 변경과 실패 안내를 가져오지 않는다.

## 검증과 남은 범위

`savedQuestionStore.test.tsx`에서 저장·재사용·삭제·재진입, 계정 분리·전환, 중복·개수 제한, 손상된 저장 값, 저장 실패 안내와 복구를 검증한다. 복구 검증에는 임시 추가·삭제와 다른 탭의 변경을 함께 포함한다.

서버 API·DB 변경은 없다. 서버 보관, 기기 간 공유, 이름 변경 등 관리 범위는 별도 정책 확정이 필요하다. 이번 구현 확인만으로 Jira 상태를 변경하지 않는다.
